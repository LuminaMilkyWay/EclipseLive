# core/changelog — 应用内更新日志（T34）

把仓库根 `CHANGELOG.md` 变成**应用内可见**的更新日志（"本次更新"弹窗 + 「更新日志」页签）。

## 为什么真源是 CHANGELOG.md，而不是另存一份

另存一份结构化副本=两份内容，必然漂移（改了一份忘另一份）。所以：
**CHANGELOG.md 是唯一真源**，主进程读取并解析，渲染层只拿结构化结果。
打包时该文件进 `extraResources`（`resources/CHANGELOG.md`）；开发态从仓库根读。

## 格式契约（解析器认得出，应用内才显示得出来）

```markdown
## [1.2.3] — 2026-01-02        ← 版本段（方括号可省；分隔符 — / – / - 皆可）
> 面向用户的一句话摘要          ← 可选引用块；"本次更新"优先展示它
### Added — 某个改动            ← 小节
- 条目（一行一条；折行的续行会并入上一条）
```

- 非版本二级标题（如 `## [Unreleased]`）会**结束**当前版本段 —— 否则它的条目会被并进上一个版本。
- 应用内只展示**最近 3 个版本**（`CHANGELOG_IN_APP_VERSIONS`）；更早的仍在 CHANGELOG.md 里。

## 降级策略

读不到文件（缺文件/权限/打包遗漏）时返回空列表并记 warn，**绝不抛**：
更新日志缺失不该影响软件启动；同时 `showWhatsNew` 为 false，避免弹一个空对话框
（"当前版本不在更新日志里"同理，例如刚改了版本号还没写日志）。

## 分层

- `parseChangelog` —— 纯函数，可直接单测；对畸形输入返回 `[]`
- `createChangelog` —— 注入文件读取与配置（Electron-free），负责"是否需要弹一次"与已读记录

见 `tests/unit/changelog.spec.ts`：其中一条测试直接解析**真实 CHANGELOG.md**，
既是解析器测试，也是格式契约守卫（格式写坏 → 应用内日志静默变空 → 该测试先红）。
