# AGPL 合规指引（给分发者与集成方）

> 本文帮助你**合规地**使用 EclipseLIVE。它不是法律意见；如有疑问请咨询专业律师。
> 协议边界总览见 [`NOTICE`](../NOTICE)。

## 一、一句话

**遵守 AGPL-3.0 即可免费商用**（含闭源商用）；**不愿承担 AGPL 义务**（尤其是第 13 条网络服务条款）
的组织，请申请 [商业授权](../COMMERCIAL_LICENSE.md)。

## 二、只分发本地软件（不分发网络服务）

- 你是**分发者** ⇒ 必须随二进制提供**完整对应源码**（含你的修改），并保留全部版权与许可声明；
- 保留 `LICENSE` / `NOTICE` / 各模块的 `LICENSE`（`modules/*/LICENSE`）；
- 你的**修改**同样按 AGPL-3.0 授权（不能改成闭源）。

## 三、把 EclipseLIVE 作为网络服务提供（AGPL 第 13 条）

- 必须向**通过网络与之交互的用户**提供**对应源码**（通常是在界面上放一个显眼的源码链接）；
- 若你**不修改**核心，指向原仓库即可：**https://github.com/LuminaMilkyWay/EclipseLive**
- 若你修改过 ⇒ 必须提供**你的**修改版源码。

## 四、只写模块（最常见）

- 你的模块**只通过** `src/contracts/`（**MIT**）与宿主通信 ⇒ **模块是你的独立作品**，
  **协议由你自选**（MIT、Apache-2.0、专有、闭源收费均可）；
- 请在模块包内放 `LICENSE`，并在 `manifest.json` 里声明 `license`（SPDX 标识符）；
- 声明了真实协议却**没有**许可证文件 ⇒ 宿主的**打包闸门会拒绝打包** ✗；
- `UNLICENSED`（专有/未授权）⇒ 允许打包且不要求许可证文件；
- **不要**复制宿主核心代码进模块 ✗（那会让你的模块变成 AGPL 衍生作品）。

## 五、商标

- 代码可用，但**不得**使用 `EclipseLIVE` 名称/图标作为你的产品名或暗示官方背书 ⇒
  见 [`TRADEMARK.md`](../TRADEMARK.md)。

## 六、自查清单

- [ ] 分发了二进制 ⇒ 同时提供对应源码（且未改协议）
- [ ] 提供网络服务 ⇒ 界面上有源码入口
- [ ] 保留了 `LICENSE` / `NOTICE` / 模块 `LICENSE`
- [ ] 没有使用本项目标识作为自己的品牌
- [ ] 模块内不含宿主核心代码
